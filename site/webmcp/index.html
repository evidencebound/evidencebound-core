Human-only control boundary

Authority and correction

These controls are deliberately not WebMCP tools. The agent can request authority; it cannot grant, restore, correct, or revoke it.

60-second judge path

Prove that correction changes future agent behavior.

  1. Inspect. Ask the agent to call inspect_release_control. It should report HUMAN_REQUIRED.
  2. Request. Ask it to call request_release_authority. A pending request appears, but authority remains human-only.
  3. Grant. Click Grant exact evidence snapshot. State becomes AUTHORIZED and execute_authorized_release appears.
  4. Execute. Ask the agent to call the execution tool. A tab-local controlled receipt is created; no external deployment occurs.
  5. Correct. Click Correct security evidence. State becomes INVALIDATED and the execution capability is removed. A retained stale callback is separately covered by the adversarial test and still fails closed.

What WebMCP changes

evidence→authority→tool surface→execute-time recheck→receipt / refusal

Without WebMCP, the agent loses the structured capability surface whose lifecycle is being controlled. Without the EvidenceBound gate, that surface does not encode current authority.
