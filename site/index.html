The problem

A valid action can become stale while the agent is still working.

Identity, permission or approval may be correct at the start of a workflow and wrong by the time a consequential action executes. EvidenceBound tests whether control follows the changing basis for authority rather than the original decision alone.

Who it is for

Start with agents that can change production or security state.

DevSecOps agents

Build, deploy, configure infrastructure or continue after code, artifact, approval or security state changes.

Cyber-remediation agents

Rotate credentials, change IAM, isolate hosts, modify firewall state or continue after incident conditions change.

The same control problem may apply to infrastructure and other consequential workflows.

What we test

Four control transitions that can invalidate previously valid authority.

Approval change

Can revoked or superseded approval still reach a consequential effect?

Evidence or policy change

When the basis changes, is materially dependent state invalidated while unrelated valid work remains intact?

Uncertain outcome

If a prior consequence may have committed, can the system create another consequence without an authorized recovery decision?

Recovery authority

Does the need to repair, compensate or retry incorrectly create fresh authority?

Claim boundary. Properties outside the tested conditions are reported as unverified rather than promoted into a PASS claim.
How an assessment works

Five steps from scope to evidence-backed findings.

The starter check includes Scope, Challenge, Observe and Report. Retest is a separately scoped option.

ScopeFreeze the consequential workflow and explicit exclusions.
ChallengeApply agreed authority, evidence, policy and outcome changes.
ObserveRetain the inputs, decisions, target contact and effects that can be evidenced.
ReportReturn findings, limitations and remediation priorities.
RetestVerify the agreed remediation under the same bounded conditions.
